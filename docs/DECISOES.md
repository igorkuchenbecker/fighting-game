# Decisões de arquitetura e projeto

| Data | Decisão | Motivo | Alternativas descartadas |
|---|---|---|---|
| 2026-08-22 | Projeto criado em `~/fighting-game/` | `~` (HOME) não estava vazio | usar `~` diretamente |
| 2026-08-22 | raylib obtido via `FetchContent` (GitHub, tag `5.5`) | stack exige raylib sem editor de engine; build reprodutível sem depender de pacote do sistema | pacote `raylib` do repositório Arch (não estava instalado); git submodule |
| 2026-08-22 | Flags de warning/sanitizer aplicadas via `CMAKE_CXX_FLAGS` nos presets, não em `target_compile_options` | `CMAKE_CXX_FLAGS` só afeta compilação C++ (nosso código); raylib é C puro, compilado com `CMAKE_C_FLAGS` — isso isola nosso `-Werror` sem quebrar o build da lib externa | flags globais via `add_compile_options` no CMakeLists (afetaria também qualquer alvo C++ de terceiros futuro) |
| 2026-08-22 | Loop de timestep fixo com acumulador (`GetFrameTime()` + `while (accumulator >= kFixedDt)`) já na F0, mesmo sem simulação real ainda | estabelece o padrão arquitetural (sim em passos discretos, render interpola/desenha último estado) exigido pelos requisitos de rollback antes que qualquer lógica de jogo exista, evitando retrabalho | `SetTargetFPS(60)` sozinho (acopla sim ao render, proibido pelos requisitos) |
| 2026-08-22 | `BUILD_EXAMPLES`/`BUILD_GAMES` do raylib forçados OFF, `BUILD_SHARED_LIBS` OFF | reduz tempo de build do FetchContent e gera lib estática (sem gerenciar `.so` no runtime) | manter defaults do raylib (build mais lento, exemplos desnecessários) |
| 2026-08-22 | Suprimir leaks de `libnvidia-glcore.so`/`libnvidia-glsi.so` via `__lsan_default_suppressions()` (só compilado quando `__SANITIZE_ADDRESS__` está definido) | driver proprietário NVIDIA aloca estado interno de contexto GL que nunca é liberado por design; ASan acusava ~6.6KB de "leak" nesse driver a cada execução, mesmo com `CloseWindow()` chamado corretamente — confirmado como falso positivo (stack trace 100% dentro de `libnvidia-*.so`, nenhum frame do nosso código ou do raylib) | `ASAN_OPTIONS=detect_leaks=0` (mascararia leaks reais também); ignorar o warning manualmente a cada rodada (não é automatizável/verificável em CI) |

| 2026-08-22 | `Direction8` usa `Left`/`Right` absolutos, não `Forward`/`Back` relativos a um oponente | ainda não existe P2 nem conceito de "de costas" (chega na F4); semântica relativa antes disso seria enganosa | codificar `Forward`/`Back` desde já com um "facing" fixo provisório |

| 2026-08-22 | Câmera fixa implementada implicitamente (coordenadas de mundo = coordenadas de tela, sem `Camera2D` explícito) | nada ainda dá scroll/zoom; um objeto `Camera2D` parado seria só cerimônia sem efeito observável | criar `Camera2D` já agora "para o futuro" (YAGNI) |
| 2026-08-22 | Direção sempre controla velocidade horizontal, mesmo no ar (sem restrição de "controle aéreo") | mantém a F1 simples; pulo para frente/trás já funciona (segura direção ao pular) | modelar aceleração/inércia aérea separada da terrestre (prematuro antes de haver golpes aéreos na F5) |
